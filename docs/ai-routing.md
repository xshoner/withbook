# 용도별 AI 연결

책 설정 → AI 설정에서 기본 연결과 요약, 목차·개요, 본문 집필, 교정·퇴고, 문체 분석, 각주 연결을 각각 지정한다. 설정은 모든 책에 공통이며 변경은 기존과 같이 관리자만 가능하다. 지정하지 않은 용도는 기본 연결을 사용한다.

## Gemini 빠른 모델 추가

1. **요약**을 선택하고 **Gemini 3.8 Flash로 설정**을 누른다.
2. 발급받은 Gemini API 키를 입력한다. 주소와 모델(`gemini-3.8-flash`), 추론 강도(`low`)는 자동으로 채워진다.
3. **저장하고 연결 점검**을 누른다. 저장은 즉시 적용되며 점검 실패 시 오류가 표시된다.
4. **목차·개요**에서도 같은 모델을 쓰려면 복사할 연결로 **요약**을 선택하고 **이 연결 복사**를 누른다. 키는 서버 안에서 복사한다. 이후 두 설정의 변경은 독립적이다.
5. 본문 집필은 기존 기본 연결을 그대로 쓰거나 별도 연결을 추가할 수 있다.

별도 연결을 없애려면 **개별 연결 해제**를 누른다. API 키를 비우면 기존 키가 유지된다. **저장된 키 지우기**를 선택하면 해당 서버 환경변수의 키를 사용한다. 다른 제공자나 주소로 변경할 때는 기존 키를 자동으로 전송하지 않으며 새 키 또는 명시적인 키 지우기가 필요하다.

Google 공식 연결 방식: https://ai.google.dev/gemini-api/docs/openai

## 저장과 호출

- 기존 `AppSetting`의 `ai` 항목은 기본 연결로 계속 사용한다. 별도 연결은 `ai:summary`, `ai:outline`, `ai:writing`, `ai:revision`, `ai:style`, `ai:footnote`에 저장한다. DB 스키마 변경은 없다.
- `src/lib/ai/routing.ts`가 기존 호출의 `purpose`를 연결 용도에 대응시킨다. 미등록 작업은 기본 연결로 돌아간다. 지정된 연결의 오류를 다른 제공자로 자동 전환하지 않는다.
- 연결 점검도 선택한 용도의 저장된 설정으로 실행한다. Gemini의 추론 강도는 Gemini 제공자에만 전송한다.
- 절 요약은 같은 서버 프로세스에서 같은 원고의 중복 요청을 공유한다. 완료 후에는 DB 요약 캐시를 사용한다. 서버 인스턴스가 서로 다르면 동시 호출이 중복될 수 있다.
- 요약 생성 중 본문이 수정되면 이전 본문의 요약으로 DB 캐시를 덮어쓰지 않는다.

검증: `npm test`, `npm run typecheck`, `npm run build`. 실제 응답 시간과 모델 이용 가능 여부는 등록한 API 키의 연결 점검 및 집필로 확인한다.
