# 전체 자동 집필

편집기 상단 **⚡ 전체 자동 집필**(다중 집필 옆). 첫 장부터 마지막 장까지 절마다 **집필 → 팩트체크 → 검수**를 AI가 진행한다.

## 시작 전 점검 (시작 창)

- 프로젝트 설정: 제목·주제·집필 의도·대상 독자
- 목차: 집필할 절이 있어야 한다(요지가 빈 절은 경고)
- 집필 추가 지시: 입력하거나 "추가 지시 없이"를 고른다 — 모든 절에 적용
- AI 연결: 집필(`writing`)·팩트체크(`factcheck`)·검수(`revision`) 용도에 키가 있어야 한다
- 옵션: 본문이 있는 절도 새로 쓰기(끄면 집필은 건너뛰고 팩트체크·검수만) · 앞붙이·뒷붙이 포함 · 팩트체크 · 검수(교정만 / 교정+가벼운 교열)

## 진행 방식 (`src/components/editor/autoWrite.ts`)

- 호출 하나가 서버 시간 한도(약 4분)를 넘지 않도록 브라우저가 절 단위로 부른다. 긴 절은 기존 자동 이어 쓰기(resume)를 그대로 쓴다.
- **집필 줄**: 책 순서대로 한 절씩 쓴다. 다 쓰면 점검을 기다리지 않고 다음 절로 간다.
- **점검 줄**: 집필이 끝난 절을 순서대로 받아 팩트체크(`[확인 필요]` 표시마다 `POST /api/projects/[id]/factcheck`) → 검수(`proofread` → `proofread/apply`, 결과는 [교정 내역]에 보관)를 한다. 다음 절 집필이 끝나 있으면 바로 넘어가고, 아니면 끝나기를 기다린다.
- 점검 중인 절은 편집기에서 잠그고, 끝나면 고친 원고를 다시 불러온다. 바꾸기 전 원고는 버전 기록(AI 집필 전·AI 팩트체크 전·교정 전)에 남는다.

## 서버 시간 한도(요청 하나 약 4분)

- 긴 절(5쪽 초과)은 파트마다 나눠 쓰고, 한 요청이 150초를 넘기면 같은 개요로 다음 요청을 이어 보낸다.
- 짧은 절이 한 번의 호출에서 한도(시간·출력 토큰)에 걸려 끊기면 완료로 두지 않는다. 그 절을 잠그고 끊긴 반쪽 문장을 지운 뒤 남은 분량을 [뒤에 이어쓰기]로 붙인다(최대 2번). 그래도 끝나지 않으면 진행 창에 "절 끝을 확인하세요"를 남긴다.
- 검수는 절을 약 6,000자(문단 단위)씩 나눠 요청 여러 개로 교정하고, 모은 수정안을 한 번에 적용한다. 교정 전 원고 버전은 첫 요청에서만 남긴다.

## 멈춤 대비

- 진행 상태는 단계가 바뀔 때마다 `AppSetting autowrite:{책 id}`에 저장한다(`/api/projects/[id]/autowrite`). 진행 중인 창은 20초마다 소식을 남긴다.
- 호출이 실패하면 인터넷 연결을 기다린 뒤 5초·20초·60초 간격으로 다시 한다(단계마다 최대 4번). 키·주소 같은 설정 오류는 바로 실패로 넘긴다.
- 두 절 연속 집필에 실패하면 일시 정지하고, 3분 뒤 실패한 단계부터 자동으로 다시 시도한다(한 화면에서 최대 3번).
- 창을 닫거나 새로 고치면 진행을 놓았다고 서버에 알린다(sendBeacon). 다시 열면 10초 뒤 멈춘 곳부터 자동으로 이어 간다. 끊길 때 진행 중이던 단계는 처음부터 다시 한다.
- 한 번에 한 창만 진행한다. 다른 창이 1분 안에 소식을 남겼으면 이 창은 지켜보기만 하고, 그 창이 닫히면 이어 받는다.
- 진행 중에는 화면이 꺼지지 않게 한다(Wake Lock 지원 브라우저). 탭을 닫으려 하면 한 번 묻는다.
- 상단 [■] 또는 Esc로 쓰던 절을 멈추면 전체가 일시 정지된다. 진행 창에서 [이어서 진행]·[실패한 단계 다시]·[끝내기]를 쓸 수 있다.
