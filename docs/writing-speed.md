# 집필 준비 시간 단축

## 집필 시 요약 AI 호출 없음

집필 경로는 앞 내용을 요약하는 AI 호출을 하지 않는다. 현재 본문 해시와 일치하는 요약만 사용하고, 없거나 수정 전의 요약이면 최신 원문에서 문단을 추출한다. 비어 있는 절의 예전 요약은 사용하지 않는다.

최근 작성된 3개 절을 우선 확보하고, 남은 범위에는 현재 절 제목·요지·스케치·추가 지시와 단어가 겹치는 앞 절을 우선 선택한다. 먼 절의 관련 내용도 포함할 수 있다. 각 발췌에는 장·절·제목과 문단 번호를 붙이고 책 순서대로 전달한다. 문맥 예산은 5,000자이며 직전 절의 끝부분은 별도로 최대 800자를 제공한다. 긴 문단은 관련 단어 주변을 발췌하고 생략을 표시한다.

변경된 절 요약의 백그라운드 갱신은 유지한다. 집필에서 사용하지 않는 장 전체 요약은 추가 생성하지 않는다. 요약 중 원고가 바뀌면 이전 본문의 결과로 캐시를 덮어쓰지 않는다. 본문 모델·API 키·추론 강도 설정은 바꾸지 않는다.

## 본문 호출 수 줄이기

- 쪽수 대신 목표 글자 수와 집필 모델의 설정된 출력 한도로 호출을 나눈다. 기본 32,000토큰 설정에서는 5,000자 이하를 별도 개요 호출 없이 한 번에 쓴다(쪽당 700자라면 6~7쪽도 해당).
- 출력 한도가 낮으면 추론 여유와 10% 여유분을 고려해 한 호출의 목표 글자 수를 낮춘다. 이는 보수적인 추정이며 실제 모델의 토큰화·속도에 따라 출력이나 시간 한도에 도달할 수 있다.
- 더 긴 절은 기존 개요의 인접 파트를 한도 안에서 묶는다. 소제목·논점·스케치 항목의 순서를 유지하고, 각 호출에는 그 호출에 배정된 분량만 요구한다.
- 큰 파트는 한도 안에서 다시 나누며 소제목을 중복 출력하지 않는다. 응답이 출력 한도에 걸리면 뒤 파트를 시작하지 않고 작성된 부분을 보존한다.
- 요청 전체 240초 예산과 새 파트 시작 150초 기준은 유지한다. 독립 여부를 확인하지 않은 절을 임의로 병렬 집필하지 않는다.

## 편집 중 미리 준비

- 본문 자동 저장 성공 후 20초간 변경이 없으면 해당 절을 요약한다. 다시 입력하면 대기를 취소하고 다음 저장 후 재예약한다. 저장 실패·미저장 원고에는 준비 요청을 보내지 않는다.
- AI 집필 완료·새 버전 채택 후에는 저장된 원고 요약을 바로 예약한다.
- 준비 작업은 변경된 절 하나만 요약한다. 다른 절이나 장 전체를 연쇄적으로 요약하지 않는다.
- AI 옵션을 열고, 5,000자 초과 목표와 스케치가 있으며, 저장이 완료되었으면 20초 후 새로 쓰기용 개요를 준비한다. 서버에서도 설정된 한도를 확인해 불필요한 개요를 생성하지 않는다. 준비 과정은 원고와 버전을 만들거나 변경하지 않는다.
- 브라우저에서 예약된 준비 작업은 하나씩 실행한다. 탭을 닫으면 아직 시작하지 않은 예약은 사라지며 실제 집필 시 필요한 내용을 정상적으로 준비한다.

## 개요 재사용

`AppSetting`의 `ai:outline-cache:<sectionId>`에 절당 최근 개요 하나를 보관한다. 유효 기간은 24시간이며 만료된 값은 재사용하지 않는다. 새로 준비하면 같은 행을 교체하고, 만료된 행은 프로젝트 목록의 일일 정리 때 삭제한다. 스키마 변경은 없다.

렌더링된 전체 프롬프트와 개요 모델의 제공자·주소·모델·추론 강도·출력 한도를 SHA-256으로 비교한다. 분량, 스케치, 추가 지시, 앞뒤 내용, 책 정보, 문체, 프롬프트 규칙이 바뀌면 재생성한다. 이어쓰기는 기존 본문을 포함한 프롬프트가 달라 새로 쓰기 개요를 재사용하지 않는다. 키 원문은 캐시에 들어가지 않는다.

## 시간 측정

AI 옵션의 **최근 집필**을 펼치면 원고 조회, 앞 문맥 선택, 개요 준비, 본문 생성 시간을 확인한다. 첫 본문 시간은 모델의 첫 출력 시점이며, 긴 절은 모델이 쓰는 소제목이 포함될 수 있다. 본문 생성 시간은 모델의 첫 응답 대기와 여러 파트 사이 대기를 포함한다. 총 시간은 서버 집필 함수의 시작부터 완료까지이며, 브라우저 네트워크·완료 후 원고 저장 시간은 포함하지 않는다.

현재 탭의 최근 결과를 절별로 최대 100개 보관한다. 서버에는 `[write-timing]` 구조화 로그로 완료·오류·중단과 단계별 시간을 남긴다. 로그에 프롬프트·원고·API 키는 포함하지 않는다.

검증: `npm test`, `npm run typecheck`, `npm run build`. 실제 시간 개선 폭은 같은 분량·모델에서 캐시가 없는 첫 집필과 준비가 끝난 집필을 비교해 확인한다.
